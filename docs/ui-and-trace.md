# UI And Trace

The UI keeps conversation, audit state, citations, and pending actions visually
separate. The goal is a normal chat experience with inspectable agent behavior attached
when relevant.

## Markdown Renderer

Assistant `ChatMessage.content` is stored as raw Markdown and rendered only in the Chat
UI. The renderer uses:

- `react-markdown`
- `remark-gfm`
- `rehype-sanitize`

Supported display features include headings, ordered and unordered lists, bold and
italic text, inline code, fenced code blocks, GFM tables, blockquotes, and links.

Safety rules:

- raw HTML is skipped and sanitized;
- user messages remain plain text with preserved line breaks;
- external links open with `target="_blank"` and `rel="noopener noreferrer"`;
- Agent Summary, Pending Actions, and Citations stay outside the Markdown answer body.

## Agent Status UI

While a Chat send is in progress, the transcript shows a lightweight status card under
the new user message. It can advance through stages such as understanding the request,
combining memory, deciding structured handling, calling the provider, parsing response,
and composing the answer.

The server remains the source of truth. `sendMessage` persists `AgentRun` and
`AgentStep` records through the router and workflows. After the assistant message is
saved, Agent Summary displays the persisted steps.

## Agent Summary

Assistant messages can show a collapsible Agent Summary with:

- detected intent;
- action level;
- evidence sufficiency;
- created objects;
- pending MemorySuggestion count;
- AgentRun link;
- citations and context refs;
- provider/model metadata;
- latency and JSON parse diagnostics when available.

The user-facing trace is limited to operational decisions, workflow steps, created or
skipped objects, citations, provider metadata, and concise errors. It does not display
hidden reasoning or chain-of-thought.

## Pending Action Counts

Pending count logic lives in `lib/pending-actions/service.ts` so UI components do not
invent their own filters.

Main functions:

- `getPendingActionsForThread(threadId)`
- `getPendingActionsForMessage(messageId)`
- `getPendingCountsByThread(threadIds)`
- `getPendingReviewSummary()`

Thread-level counts power sidebar and Home summaries. Message-level counts show pending
actions generated by one assistant message / AgentRun. Accepted or rejected memory
suggestions, resolved risks, answered open questions, archived threads, and deleted
items are excluded from active pending counts.

## Review Surfaces

Pending actions are reviewed closest to the context that generated them:

- Memory updates appear under the assistant response and in Agent Runs.
- Opportunity follow-ups live with the Opportunity and source assistant response.
- Home summarizes pending counts and links back to Chat, Opportunities, or Agent Runs.

This keeps the app from becoming a large global approval queue while preserving audit
links back to the source context.
